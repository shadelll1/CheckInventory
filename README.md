## Возможности

- Выдача инвентаря сотруднику с проверкой заполнения документа
- Возврат с контролем остатков — вернуть больше, чем числится, платформа не даст
- Ввод возврата на основании выдачи с автозаполнением табличной части
- Кнопка «Заполнить по остаткам» — подставляет всё, что числится за сотрудником
- Печатный акт выдачи на макете табличного документа
- Отчёт на СКД: остатки и стоимость по подразделениям и сотрудникам на выбранную дату
- Загрузка справочника из CSV с одновременной записью цен

## Запуск

Нужна платформа 1С:Предприятие 8.3, файлового режима достаточно.

1. Создать пустую информационную базу без конфигурации.
2. Конфигуратор → **Конфигурация → Загрузить конфигурацию из файлов**, указать папку `src`.
3. Обновить конфигурацию базы данных (**F7**).

В пользовательском режиме появится раздел «Учёт инвентаря». Демо-данные — обработка «Загрузка инвентаря из файла» и [`data/inventory.csv`](data/inventory.csv): 14 позиций с ценами, формат `Наименование;ИнвентарныйНомер;Цена`, UTF-8. Повторный запуск обновляет существующие элементы, а не плодит дубли.

## Как устроено

12 объектов метаданных:

| Тип | Объекты |
|---|---|
| Справочники | `Подразделения`, `Сотрудники`, `Инвентарь` — иерархические |
| Документы | `ВыдачаИнвентаря`, `ВозвратИнвентаря` — оба с проведением |
| Регистры | `ИнвентарьУСотрудников` — накопления, остатки · `ЦеныИнвентаря` — сведений, периодический |
| Прочее | Константа, перечисление `СостоянияИнвентаря`, отчёт на СКД, обработка загрузки, подсистема |

**Контроль остатков** — ядро проекта. Схема «записать движения → проверить»: в регистр пишется расход, затем запрос ищет отрицательные остатки. Найден минус — `Отказ = Истина`, и платформа откатывает транзакцию проведения вместе с уже записанными движениями.

```bsl

Процедура ОбработкаПроведения(Отказ, Режим)

    Блокировка = Новый БлокировкаДанных;
    Элемент = Блокировка.Добавить("РегистрНакопления.ИнвентарьУСотрудников");
    Элемент.Режим = РежимБлокировкиДанных.Исключительный;
    Элемент.ИсточникДанных = Позиции;
    Элемент.ИспользоватьИзИсточникаДанных("Инвентарь", "Инвентарь");
    Элемент.УстановитьЗначение("Сотрудник", Сотрудник);
    Блокировка.Заблокировать();

    Движения.ИнвентарьУСотрудников.Записывать = Истина;
    Для Каждого СтрокаПозиции Из Позиции Цикл
        Движение = Движения.ИнвентарьУСотрудников.Добавить();
        Движение.ВидДвижения = ВидДвиженияНакопления.Расход;
        Движение.Период      = Дата;
        Движение.Сотрудник   = Сотрудник;
        Движение.Инвентарь   = СтрокаПозиции.Инвентарь;
        Движение.Количество  = СтрокаПозиции.Количество;
    КонецЦикла;

    Движения.ИнвентарьУСотрудников.Записать();  // чтобы остатки учли текущий документ
    ПроверитьОстатки(Отказ);

КонецПроцедуры
```

Остальное коротко: кнопка «Заполнить по остаткам» разнесена по директивам `&НаКлиенте` / `&НаСервере` / `&НаСервереБезКонтекста`; печатная форма собирает данные одним запросом, без обращений через точку в цикле; отчёт соединяет `Остатки` и `СрезПоследних` левым соединением, `Количество` и `Сумма` объявлены ресурсами; загрузка CSV идёт через временное хранилище с асинхронным выбором файла, поэтому работает и в веб-клиенте.

## Чему научился

**`МоментВремени()` не включает движения самого документа.** Переданный в виртуальную таблицу напрямую, он возвращает остаток *на начало* момента. При схеме «записали → проверяем» такая проверка не видит собственный расход и молча пропускает любой перерасход — документ проводится, остаток уходит в минус. Лечится только границей:

```bsl
Запрос.УстановитьПараметр("МоментВремени",
    Новый Граница(МоментВремени(), ВидГраницы.Включая));
```

**Проверять остатки нужно после записи движений, а не до.** Тогда виртуальная таблица уже видит текущий документ и достаточно поискать отрицательные значения, вместо ручной арифметики «было минус списываем». Записанные движения не страшны: `Отказ = Истина` откатывает транзакцию проведения целиком.

**Контекст формы стоит денег.** `&НаСервере` тащит данные формы на сервер и обратно при каждом вызове. Если процедуре нужен только запрос — `&НаСервереБезКонтекста` избавляет от этой пересылки.

**Обращение через точку в цикле — это скрытые запросы.** `Ссылка.Реквизит` внутри обхода табличной части даёт отдельное обращение к базе на каждой строке. В печатной форме заменил на один запрос.

## Ограничения

- Контроль стоит только на проведении возврата: отмена проведения выдачи, по которой уже был возврат, уведёт остаток в минус. Закрывается контролем при отмене проведения или последовательностями документов.
- Регистр отвечает на вопрос «что у сотрудника», общий запас компании не учитывается.
- Отчёт строит остатки на начало указанной даты — чтобы включить документы этого дня, нужен `КонецДня(ДатаОтчета)`.
- Печать написана вручную; в боевой конфигурации команду печати регистрируют через `УправлениеПечатью` из БСП.
